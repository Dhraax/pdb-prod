## 2026-09-17 — The host sync uses the same environment files as the local stack

`config/mysql.env`, the files the local stack already runs with, instead of

  docker-compose-pdb.yml down`: that file is not in the server directory. The

  `docker stop -t 120 nwnee_baldur && docker rm nwnee_baldur`.

## 2026-09-12 — Cooldowns count from the present and announce themselves again

**What changed.** The timelock library that gates feats, abilities and potions
was replaced with the fixed version. Three faults go with it. The clock it
compared against was read once when a script started and then reused, so
anything answered after a delay — the status messages are all delayed — was
judged against a stale time. Setting a permanent lock zeroed that shared clock,
after which every other lock the same script asked about reported itself as
still running. And every lock was created muted, which is why the "X is
available again" notice never appeared. The public interface did not change, so
no ability had to be edited; `SetTimelock` merely gained an optional trailing
`bMuted` that nothing passes yet.

## 2026-09-02 — Prestige classes finally count towards the caster level the engine uses

**What changed.** The engine has never added a prestige class to a character's
caster level. `ArcSpellLvlMod` and `DivSpellLvlMod` in `classes.2da` grant spell
slots and, by Beamdog's own definition of those columns, nothing else;
`CLMultiplier` only scales a single class. So `GetCasterLevel()` has always
returned the base class level alone, and **every spell that asks the engine
for the caster level has been running without the character's prestige
levels**. The same blindness reached spell resistance rolls and the caster
level an effect records for dispelling.

A new `inc_casterlevel.nss` computes what each casting class should gain and
writes it into the engine, on client enter, after every level up and after a
level is lost. Concretely, for a spell that asks the engine:

| Character | Caster level before | Now |
|---|--:|--:|
| Mago 15 / Archimago 5 | 15 | **20** |
| Mago 10 / Maestro de la lividez 10 | 10 | **19** |
| Clérigo 10 / Teúrgo místico 10 | 10 | **20** |
| Hechicero 10 / Discípulo de dragón 10 | 10 | **15** |
| Mago 15 / Caballero arcano 5 | 15 | **19** |

class is a 2DA edit. The only rule written in code is the four classes that
advance at every level except their first — Agente Custodio arcano and divino,

cannot express "one less".

The **Discípulo de dragón** is included on purpose. Its column has said `2` here
for a long time while vanilla says `0`, so the class has been granting five
arcane slot levels at Discípulo 10 with no caster level to match and no mention
of it in the class description. Nothing is being taken away; the caster level now
follows what the slots already did.

that function still computes its own number and does not read the engine's.

**Not claimed either way.** 177 player-castable rows of `spells.2da` name an

## 2026-09-01 — Arcane Fire took other people's spells, and could break the module until reset

Arcane Fire is armed by casting nothing: it saves the module's spell hook,
replaces it with `archmage_fire`, and the archmage's next spell is converted into
a ranged touch attack instead. The hook it replaces is **module-wide**, and
almost everything that went wrong follows from that.

**Any other player casting a spell lost it.** The interception script blocked the
spell before checking whether the caster had the feat, so while an archmage was
armed the next person in the module to cast anything - anywhere - had the slot
spent, no effect produced and no message shown. It also cleared the armed flag on
*them*, leaving the archmage armed and unable to re-arm until rest or relog.

Other casters now pass straight through to the hook Arcane Fire displaced, so the
module's own spell rules keep applying to them and nothing is lost.

**Two archmages broke the module until it was reloaded.** The saved hook was one
module-wide string. The first armed and saved `q_spellhook`; the second armed and
saved `archmage_fire` over it. From then on every restore reinstalled the
interception script, `q_spellhook` never came back, and every spell cast by
everyone stayed intercepted. The hook is now saved only when it is not already
the interception script, and a count of armed archmages decides when it comes
back out - so one archmage disarming no longer disarms another.

**Resting, logging in or logging out left the module hooked.** Rest and
client-enter cleared the armed flag without restoring the hook, and logout did
neither - so an archmage who quit while armed left the hook installed and a count
that never reached zero, which also stopped other archmages' releases from
restoring it. All three release properly now.

**A refused conversion no longer eats the spell.** Everything that can refuse -
a spell that is not a memorised wizard or sorcerer spell, one cast from an item,
a target that is gone, dead or friendly - is checked before the spell is blocked. The
spell goes off as itself and Arcane Fire stays armed for the next one. All four
cases used to spend the slot for nothing.

**A critical hit doubles the damage.** The ranged touch attack returns 2 on a
critical and the result was only tested for true or false, so a critical dealt
normal damage.

**The damage formula is unchanged and that is deliberate.** It uses the Archmage
class level plus Spell Power plus the level of the spell spent, not the total
caster level. The prestige class gives at most five levels, so the spell you burn
decides most of the damage; on total caster level a first-level slot would deal
more than a ninth does today, which turns the ability into "always spend the
cheapest thing you have".

**Cost.** While nobody is armed, nothing changed at all - the hook is not
touched. While somebody is armed, every spell cast in the module pays one extra
`ExecuteScript` to reach the real hook. `q_spellhook` is 47 KB and already ran on
every spell, so this is noise beside it.

cast any spell. It must work normally - component rules and all - and the
archmage must still be armed afterwards.

## 2026-09-01 — The Force Bazooka stops rolling its save against fire

**What changed.** The Force Bazooka deals `DAMAGE_TYPE_FUERZA` - the module's own
force damage, built on one of the engine's custom damage slots - and rolled its
Reflex save with `SAVING_THROW_TYPE_FIRE`. It now rolls with
`SAVING_THROW_TYPE_NONE`.

NWN has twenty-one saving throw subtypes and none of them is force. Unlike damage
types, which reserve custom slots, the subtype list is fixed in the engine and
item properties reference it through `iprp_savingthrow.2da`, so a force subtype
cannot be added. With no honest subtype available, the roll is made against none
at all.

**What this means for a defender.** No elemental resistance helps against the
Force Bazooka any more - fire bonuses stop applying and nothing replaces them,
which is the point: force is not an element anyone carries a ward against.

The Spellcraft compensation is granted. It is an opt-in on this route rather than
something a subtype of None gives by itself, so it is asked for explicitly - and
it is the reason None was chosen over Spell, which would have made asking for it
impossible. A defender with invested Spellcraft ranks now resists this invocation
better than one without; before this change neither of them did.

**Pending in-game test.**

A character with a large fire saving throw bonus, hit by the Force Bazooka: the
bonus must no longer help at all. Before this it did.

A defender with zero and with fifteen invested Spellcraft ranks: the second must
now resist three points better. Before this change neither of them got anything
from Spellcraft here, so this is a new bonus for the defender, not a restored
one.

Evasion and Improved Evasion must behave exactly as they did.

## 2026-09-01 — Three artificer durations changed to match the page, and all three put back

**Nothing about the artificer behaves differently after this day.** The entry
stays because the attempt is worth knowing about: three durations were changed to
match the published class page and all three were reverted, so anyone reading
that page against the code later does not repeat the work.

| | Code | Page | Decision |
|---|---|---|---|
| Secondary burning | up to 6 ticks | 5 rounds | **6 stays** |
| Protector | caster-level rounds | 5 rounds, no stacking | **caster level stays** |
| Infusion change lock | 8 seconds | 20 seconds | **8 stays** |

The Protector is the one worth spelling out, because the gap is large. A round is
six seconds, so caster-level rounds is two minutes at artificer 20 against the
thirty seconds the page describes. It grants temporary hit points equal to the
artificer's usual damage roll, to the caster or to an ally, and locks itself for
as long as they last. Cutting it to five rounds would have been a four-fold nerf
at high level, decided by a web page rather than by play.

The change lock is the same shape at a smaller scale: twenty seconds is long
enough that an artificer can do nothing at all between one infusion and the next.

**What this establishes.** The class page is the specification where it and the
code disagree **and the owner agrees with it**. It is not authority on its own,
and a difference between page and code is a question, not a defect. The five
repairs of the day before - the wrong feats, the elixir that never set its flag,
the gas bomb tiers - were defects because the code contradicted *itself*. These
three did not.

The page is now what needs correcting on these three numbers, along with the
comments beside the infusion-change check that still say twenty seconds.

**Nothing to test.** No behaviour changed. The only file that differs from the
day before carries an authorship marker and comments.

`d97fe6bb5` put the change lock back, and this one puts back the other two.
